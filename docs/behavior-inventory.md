Missing dependencies are restored from DiPlay commit 9e244d958afe6b8fd79ade49769ce25a944f397b: IphoneUsbHost, UsbMuxFrameBuffer, I2cTransport, MfiAuthenticationClient, Iap2MfiAuthenticationClient, TcpLiveness and TouchLatencyProbe. Only package destinations change. No authentication identity or signing key is copied.

For 0.19 Wi-Fi handoff, readiness also waits for actual outbound link acknowledgement within the existing authentication budget; queue acceptance is not delivery or application acceptance. The new observational drain API does not change packet bytes, windows, retry timers or legacy callers. Capture preparation/start uses the negotiated geometry before RECORD, retaining authorization and buffering real early frames in the original bounded queue. See `docs/wireless-alignment-0.19.md` for the complete behavior mapping, scoped validation and the unresolved conditional GM USB-identity requirement.

Additional restored dependencies are Ch341DeviceMatcher, IphoneCarPlayConfiguration, UsbReadQueuePolicy, UsbRequestQueue and Base64Compat. Original receiver factories retain their roles and acknowledgement profiles. Separate phone/controller factories cover Bluetooth and type-130 Wi-Fi; encrypted packages are round-tripped through the original IapTunnel receiver.

The original MediaProjection consent, callback, geometry, H.264 framing, playback-capture audio, keyframe and cleanup paths remain available in the standalone flavor. The optional ProjectionSurfaceSource adds the vivo host-owned Surface path; both paths use the same encoder outputs. Native audio has its own bounded queue and does not replace playback capture. Failed binding, display timeout and old host teardown retain explicit diagnostics.

For deferred host arrival, serialize host binding/death-registration with teardown. Closing before attach must prevent binding; closing after bind must retain the existing status notification, stop transaction, death unlink, future cancellation and unbind. Do not hold that lifecycle lock while waiting for a host callback.

The component flavor preserves the original 8.8.4 package and service/activity ABI, and reads its launch fields rather than inventing a default host. CA validation remains unchanged. BondedAccessoryTrust is a distinct, explicitly selected peer-binding policy: initial enrollment requires an authenticated paired Bluetooth channel and a valid challenge proof; Wi-Fi cannot enroll an unknown peer. MfiController retains its original CA overload.

The sample APK is a behavioral reference. Its development-trust fallback is not carried into production. Trusted accessory certificates, legitimate platform authorization, and real frame/audio evidence remain prerequisites. Hardware compatibility is established by diagnostics from a real session rather than by library class names or a successful compile.
